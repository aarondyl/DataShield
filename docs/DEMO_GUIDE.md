# DataShield 本地比赛演示（5 分钟）

本流程使用 Windows Desktop、内置 PIPL/数据安全法离线法规库、本地 SQLite，以及用户自行选择的 Ollama 或 OpenAI 兼容模型。私人产品资料不会自动同步到 Cloud。若选择 DeepSeek 或其他云端 API，必须先在设置页勾选同意，且仅发送当前分析所需的产品画像和法规证据；不会自动上传本地仓库或数据库。

## 演示前准备

1. 安装并启动 Ollama，执行 `ollama pull qwen3:4b`；或准备自己的 DeepSeek/OpenAI 兼容 API Key。
2. 启动 DataShield。首次启动进入版本选择，选择“开发者版”；之后选择“离线工作区”，输入名称创建本机工作区。
3. 打开“设置 → AI 模型配置”，选择“Ollama”并读取模型，或选择“用户自带云端模型 API”，填写 Base URL、模型名和 Key。云端 API 模式先阅读并勾选数据发送同意，再保存；完全退出并重启 DataShield。
4. 点击“测试真实推理”，确认显示实际服务商和模型名称。

## 五分钟操作

### 0:00–1:00 建立产品画像

1. 在侧边栏点击“产品”，选择“添加产品/开始理解”。
2. 第一步填写名称、简介和产品类型，例如“商户订单分析 SaaS”。
3. 第二步选择中国大陆和欧盟，描述用户注册、上传订单 CSV、云端生成销售报告等业务场景。
4. 第三步运行模型辅助整理，逐项检查事实及来源；将未知的保留期限、删除机制和子处理者标为“未知”，确认画像。

**预期：** Product Twin 显示版本号、事实来源和确认状态，未知事实不会被当作“不存在”。

### 1:00–2:00 查阅本地法规

1. 点击“法规库”。
2. 搜索“个人信息保护法”或“数据安全法”，打开条文查看正文、条款编号及官方来源链接。
3. 在 Requirement 列表确认自动提取要求为“未人工核验”。

**预期：** 首次安装联网与否都能检索 PIPL 和数据安全法；原始条文和来源在本机 SQLite。

### 2:00–4:00 运行真实模型分析

1. 点击“今日”或产品页的“运行合规检查”。
2. 等待模型根据已确认画像和本机检索的法规要求给出判断。
3. 点击 Finding，核对产品事实、适用性说明、风险等级、整改建议、法规名称、具体条款和官方来源。

**预期：** 模型不可用或未配置时分析会明确失败，不产生 Mock Finding。每条法规引用必须能在本地法规库中找到。

### 4:00–5:00 更新待办并验证保存

1. 在 Finding 详情中把状态改为“处理中”或“已处理”，查看整改建议并创建整改任务。
2. 返回“今日”，确认待办数量和状态来自真实 Finding/整改记录。
3. 退出并重新启动 DataShield，再打开同一工作区和 Finding。

**预期：** 工作区、Product Twin、法规库、Finding 和分析记录仍然存在。数据存储位置为 `%LOCALAPPDATA%\DataShield`。

## 安全边界

- 本地模式不需要账户、SMTP、Docker、WSL 或手动启动 Python。
- Ollama 请求仅发往本机回环地址。DeepSeek/兼容 API 的请求会离开设备；只有同意后才允许发送必要上下文。
- 分析结果仅作合规排查参考，不构成法律意见；自动提取要求需要人工复核。

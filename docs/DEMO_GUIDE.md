# DataShield 五分钟演示指南

本指南按 Windows 预发布安装版编写。Cloud 切换获批并完成公网验证后，按“在线演示”走完整闭环；服务上线前只能演示离线工作区和 Ollama，不能把离线模式说成 Cloud 账户或法规同步成功。

## 在线演示（Cloud 正式切换后）

### 0:00–1:00 安装并进入产品

1. 从 GitHub Releases 下载最新 `DataShield_*_x64-setup.exe` 和同名 `.sha256`。
2. 在 PowerShell 或 WSL 对照校验文件验证 SHA256，再双击安装包。
3. 启动 DataShield，选择“开发者版”，进入账户页后注册或登录 Cloud 账户。
4. 如账户要求邮箱验证，使用收到的验证码完成验证。失败时先确认 Identity 邮件发送状态，不要使用离线工作区冒充云端登录。

**预期：** 桌面窗口显示中文首页；账户和工作区来自 Identity 服务。

### 1:00–2:00 创建工作区与产品

1. 进入“工作区”，新建演示工作区 `DataShield 演示工作区`。
2. 在“产品”中添加 `RelayCart 商户分析平台`。
3. 在产品描述填写：

   > 为中国内地与欧盟商户提供托管式订单分析。商户管理员通过邮箱注册，上传订单 CSV；服务在云端保存订单和账户资料，并生成销售趋势报告。暂不清楚是否有删除周期、子处理者清单和跨境数据传输。

4. 进入“接入与理解产品”，选择手动描述并运行理解。
5. 查看每项事实及其来源；对不确定的存储区域、保留期限和子处理者维持 UNKNOWN。确认画像后查看版本号。

**预期：** 产品画像有来源及确认状态；未知事实没有被自动当成不存在。

### 2:00–3:00 同步官方法规

1. 打开“法规动态”并选择中国大陆（如演示跨境场景，再选欧盟）。
2. 点击“同步法规”。
3. 打开“法规资料库”，检索《个人信息保护法》和《数据安全法》；查看版本、官方来源链接、生效日期和核验状态。
4. 打开法规变更事件，确认首次导入事件显示法规来源和版本。自动提取要求应显示“未人工核验”。

**预期：** 法规原文和官方 URL 可打开；Requirement 的机器提取状态没有被标为人工审定。

### 3:00–4:00 运行本地合规分析

1. 在 Windows 安装并启动 Ollama，确保已有 `qwen3:4b`；也可以在 DataShield“设置 → AI 模型”选择已配置的 Ollama 模型。
2. 确认状态显示 Ollama 在线及模型 `qwen3:4b`。Ollama 推理留在本机。
3. 从“Today”或产品画像进入“运行合规检查”。
4. 在 Finding 页面打开一条结果，核对法规名称、条款、版本、官方来源、适用性结论、产品画像版本和风险说明。

**预期：** 结果由实际 Ollama 推理工作流产生，证据引用已同步到本机的法规要求；未确定事实会列为缺失上下文。

### 4:00–5:00 整改、反馈与持久化

1. 从 Finding 创建整改建议，查看具体内容后批准或拒绝。批准只代表批准建议，不代表已经执行或风险已消除。
2. 提交反馈，例如“订单文件只保留 30 天，处理完成后自动删除”。
3. 查看拟议画像修正，确认后应用并运行局部重新分析。
4. 在 Today 查看新的分析时间、未处理 Finding 和整改状态。
5. 退出 DataShield 并重新打开，确认工作区、画像版本、Finding 和整改历史仍在本机。

**预期：** 新画像版本与重分析记录可追溯；本地数据重启后仍在。法规同步不会上传私人产品资料。

## Cloud 尚未切换时

选择“离线工作区”，只演示本地工作区、产品画像和 Ollama 设置。当前 Production 尚未启用 Identity 与 HTTPS Proxy，离线模式无法证明 Cloud 注册、法规同步或云端法规检索成功。请在 `docs/DEMO_STATUS.md` 核实当日实际状态。

AI 输出和自动提取要求都需要人工核验，不构成法律意见。

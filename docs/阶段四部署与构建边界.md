# 阶段四：部署与构建边界

## 构建边界

- `backend/Dockerfile`：保留既有 Web 托管模式；构建 React 并提供网页和 Web API。
- `backend/Dockerfile.cloud`：只复制 Python 云端法规服务，不包含前端产物；以 `RUNTIME_MODE=cloud` 启动，因此不装载租户、Product Twin、Finding、Remediation 或 Feedback 路由。
- Local 继续使用现有 Electron/PyInstaller 交付物和用户应用目录 SQLite；镜像与安装包均不得内置共享 API Key 或 LLM 密钥。

## 云端部署

生产或预发布使用 `docker compose -f docker-compose.cloud.yml up --build`。必须由部署平台 Secret 提供 `postgres_password` 和完整连接串 `cloud_database_url`；应用从 `/run/secrets/` 读取，避免在 Compose 环境变量或镜像层中暴露密码。PostgreSQL 不公开端口，只加入 `cloud_database` 私有网络；Cloud 同时加入可出站的 `cloud_egress` 网络以抓取官方法规来源。Cloud HTTP 端口默认只绑定 `127.0.0.1`，由反向代理显式转发。

发布必须经过人工批准，并依序执行：构建不可变镜像、运行迁移、等待 `/api/health` 健康检查、进行法规同步冒烟验证。失败时将反向代理切回上一已验证镜像；不得用 `git archive HEAD` 或整仓复制的方式上传服务器。

Cloud 必须运行独立谱系：`alembic -c alembic-cloud.ini upgrade head`。它使用 `alembic_version_cloud`，仅创建法规表和 `vector` 扩展；**禁止**在 Cloud 容器中运行普通的 `alembic upgrade head`，后者属于 Web/Local 完整业务数据库迁移链。

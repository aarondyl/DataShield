# DataShield Windows 使用教程

当前为候选版本教程，公开下载和 Cloud 实际地址以最终报告及获批 Release 为准。没有完成验收的地址或 Artifact 不视为正式分发。

## 安装与启动

1. 在获批的 GitHub Release 下载 `DataShield_0.1.0_x64-setup.exe` 和 `SHA256SUMS.txt`。
2. Windows 11 x64 PowerShell 执行 `Get-FileHash .\DataShield_0.1.0_x64-setup.exe -Algorithm SHA256`，确认与校验文件一致。
3. 双击安装器，按当前用户安装。无需 Python、Node 或 Docker；首次安装 WebView2 Runtime 可能需要联网。安装器尚未签名，只有确认来自获批 Release 且校验一致后才继续。
4. 启动 DataShield。默认简体中文，右上角可切换 English；语言偏好重启后保留。侧栏应显示本地智能体已连接。

## 工作区、产品与画像

创建工作区和产品，填写产品用途。可录入手动事实，也可分析公开网站或通过原生选择器授权一个本地仓库。网站/仓库理解为静态提取，不执行项目代码。网站域名必须实际解析为公网地址；使用 fake-IP/保留地址的 DNS 或代理环境会被安全校验拒绝，不能通过关闭目的地校验绕过。检查结果后确认导入 Product Twin，再审核每项事实、市场、主体、功能和控制状态；审核会生成新版本并保留历史。

“未知”不等于“不存在”，“未检测到”不等于“已确认缺失”。产品画像是用户提供的事实或推断，不是法规原文。

## 配置和同步 Cloud

在设置填写最终报告中经过验收的 HTTPS Cloud 地址，不填密码或 operator token。进入法规动态点击同步，检查最近同步时间、法规来源及状态。首次纳入语料库的 `initial_import` 是同步基线，不意味着法规刚发生修订。

同步只下载公开法规，不上传产品画像、仓库文件、Finding 或反馈。Cloud 不可用时保留已有 SQLite 缓存；首次未同步时无法凭空产生正式法规。已有缓存后不能直接切换为其他来源，以免法规键和证据混淆。

来源链接本身不能证明缓存正文已核验。官方原文及其现行版本需复核；义务摘要未经人工审核时属于未核验抽取结果；`DEMO SUMMARY` 仅用于演示。当前模拟解释不能视为真实 AI 分析或法律结论。

## Finding、Evidence 与整改

运行本地合规检查。进入发现详情，查看适用性、差距、法规版本、条文正文、来源链接、不可变证据快照和使用的 Twin 版本。上下文不足时补充画像后再检查；暂无发现不表示已经合规。

从发现生成文档或代码整改建议，阅读具体草案和验收标准，填写审核意见后批准或拒绝。批准仅接受建议，不执行代码、不发布文档、不自动解决发现。实施结果需人工验证。

## 反馈、更正和重新分析

在原发现提交纠正意见。审核系统解释和候选事实；若需要澄清则补充说明。确认候选后，再点击应用修正与重新分析。确认本身不改变 Twin；应用才创建新版本并检查关联法规。重新分析失败可重试，已写入的版本及旧记录保留。返回发现和 Today 查看真实待办与最近处理事项。

## 数据、卸载与更新

产品、画像、法规缓存和业务记录保存在 `%LOCALAPPDATA%\DataShield`。退出 Desktop 后再备份该目录；不要公开其中的 SQLite 或运行时文件。`runtime.json` 含短期凭据，不分享其内容。

目前没有安全自动更新。下载新的获批 Release、验证 SHA256、退出软件并备份数据后手动安装。本轮独立 RC 的实际卸载保留 SQLite，同一个包重装后原工作区仍在；跨版本升级的数据行为仍以补充实机验收记录为准；不要把卸载当作安全删除用户数据的操作。

真实 Cloud AI Gateway、安全 BYOK 和 Ollama 尚未提供。当前确定性模拟模型只验证业务流程，软件不提供合规认证。

## 1. 这个项目是什么

DataShield（数盾）是**中文优先的 AI 数据合规助手**：用户用中文描述产品（或贴网址），AI（DeepSeek 驱动）对照 GDPR / 个人信息保护法 / 数据安全法，告诉用户哪里不合规、依据哪一条、怎么改（AI 起草整改草案，人工审阅后用）。

- 产品说明书：`docs/产品说明书.md`（含真实截图）
- 线上版：http://123.57.252.25（阿里云轻量服务器，北京）
- 桌面安装包：GitHub Release v0.1.0（`DataShield Setup 0.1.0.exe`）

## 3. 本地跑起来（5 步）

```bash
# 需要 Python ≥3.11、Node ≥20
cd backend && pip install -r requirements.txt        # 1. 装后端依赖
cp .env.example .env                                  # 2. 配置（见下节）
cd ../frontend && npm install                         # 3. 装前端依赖
cd ../backend && python -m uvicorn app.main:app --port 8000   # 4. 起后端
cd ../frontend && npm run dev                         # 5. 起前端 → http://localhost:5173
```

`backend/.env` 关键项（仓库里没有，需自己建）：

| 变量 | 值 | 说明 |
|---|---|---|
| `LLM_PROVIDER` | `mock` / `api` | mock=离线演示输出；api=真实 DeepSeek |
| `LLM_API_KEY` | 找姜睿要 | DeepSeek key（**不要提交进 git**） |
| `LLM_MODEL` | `deepseek-flash` | 即 DeepSeek-V4.1-Flash |
| `ADMIN_API_KEY` | 自设一个长随机串 | 管理后台 `/admin` 用 |
| `UNDERSTANDING_API_KEY` | 长随机串 | 产品理解子系统；**注意它经 `os.getenv` 读取，必须是真实进程环境变量**（systemd 用 `EnvironmentFile` 注入），只写 .env 不生效 |

## 5. 服务器部署（123.57.252.25）

架构：Nginx(80) → uvicorn(127.0.0.1:8000) → SQLite；systemd 服务名 `datashield`，`EnvironmentFile=/opt/datashield/backend/.env`。

更新流程：

```bash
# 本地打包（git archive + 前端构建产物作 backend/static）
mkdir -p deploy/pkg && git archive HEAD | tar -x -C deploy/pkg
cd frontend && npm run build && cp -r dist/* ../deploy/pkg/backend/static/
cd ../deploy/pkg && tar czf ../pkg.bin . && cd ..
# 上传（大文件 SFTP 会被服务器拦，必须用碎块脚本；密码走环境变量不落盘）
MSYS2_ARG_CONV_EXCL='*' DS_PASS='服务器root密码' python deploy/upload_chunks.py deploy/pkg.bin /tmp/pkg.bin
# 解压重启
DS_PASS='服务器root密码' python deploy/ssh.py exec "tar xzf /tmp/pkg.bin -C /opt/datashield && systemctl restart datashield && sleep 8 && curl -s http://127.0.0.1:8000/api/health"
```

服务器密码 / 阿里云控制台账号：找姜睿要。改完记得线上主路径过一遍。

## 6. 桌面安装包

```bash
cd desktop && npm install && npm run dist
# 产物 desktop/release/DataShield Setup 0.1.0.exe
```

- 打包前：`taskkill //IM DataShield.exe //F //T`（否则文件锁定失败）；前端构建用 `npm --prefix ../frontend run build -- --base=./`
- 桌面后端（`backend/desktop_entry.py`）：只绑 127.0.0.1:18321；每次启动 Electron 发随机 runtime token（防本机盗用）；启动自动 `alembic upgrade head`（失败回滚备份）；数据在 `%APPDATA%\DataShield`
- **内置 DeepSeek key**：由 `deploy/gen_bundled_key.py` 构建期生成混淆模块（gitignored，仓库里看不到 key）；换 key 后重跑该脚本再打包
- winCodeSign 解压坑（7za wrapper）见 `desktop/README.md`
- 发新版 Release：GitHub → Releases → 新建 tag 上传 exe（或调 API）

## 8. 产品逻辑速览（改代码前读）

主线：`描述产品（onboarding 三种方式+手动）→ 产品画像（product_twin_facts，可纠正）→ 适用性分析（tenant agent，确定性规则优先+LLM）→ 合规发现（findings，四段式展示）→ AI 整改草案（remediations，DeepSeek 起草，人工审阅采纳/拒绝）→ 反馈纠正（feedback candidates，确认后回写画像并重分析）`。法规侧：`regintel` 维护法规版本/条文/义务提取/语义检索（pgvector 或本地哈希向量），管理后台 `/admin` 管用户/工作区/法规/演示数据/系统状态。

## 9. 约定与坑

- **语言**：中文优先。新 UI 文案先进 i18n（zh 为原生，en 为自然英文）；后端面向用户的生成内容用中文模板；LLM prompt 要求中文输出
- **枚举**：后端枚举键保持英文，前端展示走映射（参照 appnew.ts 各 `*Status`/`*Type` 段）
- **数据库**：本地/服务器用 SQLite；PostgreSQL+pgvector 切换只改 `DATABASE_URL`；新模型字段必须出 alembic 迁移 + `init_db` 的 SQLite 兜底 ALTER
- **鉴权**：cookie 会话（evaluation_auth）；旧版 `/api/companies` 等由 `legacy_tenant_api_enabled` 整体开关（默认关）
- **已知边界**（可做下阶段）：登录后再登录不自动恢复上次工作区；事实纠正的候选定位偶发跑偏；HTTPS 未配（需域名+ICP 备案）；安装包未签名
- 前端无 UI 组件库，样式是手写 ds-* 体系（`frontend/src/styles/`），新页面沿用；Tailwind 仅允许在新组件用工具类
